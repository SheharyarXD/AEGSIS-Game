# AEGIS hero — asset workspace

Everything needed to rebuild the two playable characters:

| Output | What it is |
|---|---|
| `public/assets/aegis-hero.glb` | The AEGIS armour: original model, baked maps, rig, 44 clips, 6 thruster mounts, 2 missile mounts, 67 assembly groups |
| `public/assets/aegis-pilot.glb` | The unsuited pilot, rigged to the same skeleton and clips (**placeholder, non-commercial** — see `aegis-pilot.provenance.json`) |
| `aegis-hero.blend`, `aegis-pilot.blend` | Editable Blender sources: game mesh, UVs, textured materials, rig and all clips. The armour's 8-million-triangle high-poly is regenerated by `build.py` and is left out unless you pass `--keep-high` |

## Requirements

- Blender 4.5 LTS. The portable build lives in `tools/blender-4.5.14-windows-x64/` (git-ignored). Any Blender 4.5 works; adjust the path below.
- Node dependencies from the project root (`npm install`).

## Rebuild

From the project root (PowerShell or Git Bash):

```bash
# 1. skeleton + clips out of the old operative GLB (only needed once)
node scripts/prepare-hero-rig.mjs

# 2. armour: model, decimate, unwrap, bake, skin, export  (about 6 minutes)
tools/blender-4.5.14-windows-x64/blender.exe -b --factory-startup -P art/aegis-hero/build.py -- --quality 1.0 --tex 4096 --export
node scripts/finalize-hero.mjs aegis-hero

# 3. pilot: fit skeleton, skin, export  (under a minute)
tools/blender-4.5.14-windows-x64/blender.exe -b --factory-startup -P art/aegis-hero/build_pilot.py
node scripts/finalize-hero.mjs aegis-pilot

# 4. look at it in a real browser and capture the review set
node scripts/hero-qa.mjs            # screenshots -> artifacts/hero-qa/
node scripts/hero-capture.mjs       # videos, frame strips, foot-slip numbers -> artifacts/hero-video/
npm run dev                         # then open /scripts/character-preview.html
```

Changing only the motion or the assembly grouping does not need the six-minute bake.
`tools/remotion.py` re-authors the clips on the saved `aegis-hero.blend` in about 15 seconds:

```bash
# rebuild the armour's clips from the mocap sources, save, export, finalise
blender -b --factory-startup -P art/aegis-hero/tools/remotion.py -- --save --export
node scripts/finalize-hero.mjs aegis-hero

# try retarget settings or another capture without saving (renders into renders/)
blender -b --factory-startup -P art/aegis-hero/tools/remotion.py -- --render --rest --set pronation=20,level=0.9 --tag trial
blender -b --factory-startup -P art/aegis-hero/tools/remotion.py -- --render --clip aegis_walk=91_33 --frames 0,6,12,18,24 --tag macho
```

Fast iteration on the armour (no bake, Blender renders into `renders/`):

```bash
blender -b --factory-startup -P art/aegis-hero/build.py -- --quality 1.6 --clay --pose 60:Idle-cycle --render front,side,back,helmet
blender -b --factory-startup -P art/aegis-hero/build.py -- --only helmet --quality 1.0 --clay --render helmet,helmet_side
```

## How the armour is made

The suit is authored as code, but it is real modelled geometry, not stacked primitives:

1. **Skeleton** (`hero/rig.py`). The gameplay skeleton and clips are imported and
   re-proportioned to a 185 cm heroic human by *translating* bone subtrees (never
   rotating them), so every rotation keyframe keeps its meaning. The source rig's
   double-hinged elbows and knees are pulled to 2.5 cm apart so they read as single
   joints; the middle bone carries the elbow cop / knee cap at the half angle.
2. **Body** (`hero/anatomy.py`). An anatomical body is defined as a signed distance
   field (smooth-blended muscle volumes). It is the undersuit and the reference
   surface for the armour.
3. **Armour plates** (`hero/armor/*.py`). Each plate is an offset shell of the body
   with an exact outline (front/side/top projections, or outlines drawn on the
   "unrolled" surface of a limb), plane-cut facets, chamfered borders, recessed
   channels and panel lines. The helmet is a faceted wedge skull with a recessed
   visor and layered overlay plates. 200+ parts in total, each bound to one bone.
4. **Meshing** (`hero/mesher.py`). Narrow-band Surface Nets with gradient projection,
   1–2 mm voxels: about 8 million high-poly triangles.
5. **Game mesh** (`hero/export.py`). Per-part decimation, removal of permanently
   hidden faces, region-growing planar UV unwrap into one atlas, then Cycles bakes
   from the high-poly through a cage: tangent-space normals, ambient occlusion and a
   wear / roughness mask (edge highlights, cavity darkening, brushed streaks).
6. **Skinning**. Plates are rigid (one bone each); the undersuit uses smooth weights.
7. **Finalise** (`scripts/finalize-hero.mjs`). One shared 2K texture set (albedo
   variation, normal, occlusion-roughness-metal) on six surface materials, WebP,
   quantised geometry, resampled animation, manifest.

## Motion

Idle, walk and run are retargeted motion capture (`hero/motion.py`), one set per form
so the pilot and the armour carry themselves differently:

| Clip | Pilot | Armour |
|---|---|---|
| `aegis_idle` | CMU 77_02, arms at his sides | CMU 77_02, fists, flared elbows, wide stance, head lowered |
| `aegis_walk` | CMU 91_22, 1.35 m/s, relaxed | CMU 08_05, 1.68 m/s, heavy and aggressive (see below) |
| `aegis_run` | CMU 16_55, 3.55 m/s | CMU 09_01, 3.46 m/s, fists |
| `aegis_suitup` | authored stance | authored stance |

How a clip is made:

1. One gait cycle is cut between two matching heel strikes and its heading is turned
   to face forward. Lead-in frames are cross-faded into the tail to close the loop.
2. Each bone is aimed along the direction of the matching captured limb, so the
   result does not depend on the two skeletons having the same proportions.
   Forearm roll is replaced by a relaxed, calibrated pronation; `level` lifts the
   head of a subject who watches the floor.
3. Posture is then shaped per form with a handful of options: `arm_spread` (how far
   the arms hang from the body), `elbow_keep` / `elbow` (relax or add elbow bend),
   `arm_swing`, `finger_curl` (loose hand to clenched fist), `clavicle` (how much
   collar-bone motion is kept, so the shoulders stay level and paired), `torso_sway`,
   `lean`, `chin` and `stance` (step width). The armour's aggressive walk is the same
   capture as a neutral stride with these turned up.
4. The pelvis is set so the lowest sole touches the floor, then two-bone leg IK
   plants each foot. **Foot lock:** while the ball of a foot is on the floor it is
   held on a straight line moving back at exactly the pace the clip covers ground,
   and a swinging foot is kept clear of the floor.
5. The clip's ground speed is written to `export/<name>.motion.json` and embedded in
   the GLB. The game advances the gait by distance covered, not by time, so the feet
   keep pace with the body at any speed.

Tune a form's set in `SETS` at the bottom of `hero/motion.py`. To audition another
capture on the pilot: `blender -b --factory-startup -P art/aegis-hero/tools/motion_review.py -- 91_22 16_55`.

The captures are from the Carnegie Mellon University Motion Capture Database
(`source/mocap/`, BVH conversion by B. Hahne), free for research and commercial use.
Required credit: *The data used in this project was obtained from mocap.cs.cmu.edu.
The database was created with funding from NSF EIA-0196217.*

### Cleaning the capture

Three things keep the legs steady, all applied before the clip is written:

- The capture is 120 fps data taken at every fourth frame; it is low-pass filtered
  first, or marker jitter aliases into a constant shake.
- The leg IK takes its bend direction from the knee's offset *and* the thigh's own
  forward axis, so a nearly straight leg has a defined bend plane, and it never drives
  the leg fully straight.
- Toes bend continuously against the floor instead of switching between two rules.

`build_set` prints a `twitch` figure per clip: the largest change in a leg bone's turn
between successive frames. A spike there is an IK flip.

### Authored clips

Flight, free fall and the landings are keyframed poses in `hero/clips.py`: limb
directions per key, eased in world space and sampled at 30 fps by `motion.key_clip`.
Flight poses are authored upright; the game pitches the body by its real velocity.
Grounded clips stand on the floor: the pelvis sits where the lowest sole or knee
touches, feet are planted and locked, and a fist asked onto the floor is put there by
arm IK (the three-point landing). `aegis_bank_l` / `aegis_bank_r` are layered
additively over the other flight poses at runtime.

Preview any of them without a bake:

```bash
blender -b --factory-startup -P art/aegis-hero/tools/remotion.py -- --render --tag look \
    --shots aegis_hover:0,aegis_cruise:0,aegis_boost:0,aegis_land_heavy:8 --views front,side
```

The combat set is authored the same way, planted on the floor: `aegis_stance`, the
combination `aegis_jab` / `aegis_cross` / `aegis_hook`, `aegis_heavy`, `aegis_guard`,
`aegis_counter`, three dodges and the airborne `aegis_air_strike`. Every strike starts
from and returns to the same stance pose, so they chain without a pop. Their timing
(active frames, chain windows) lives with the gameplay, in `src/combat/Melee.ts`.

Jump and flinch are still the rig's original clips.

## Assembly groups

The suit-up moves real armour sections, so every vertex carries a `_GROUP` attribute
naming the rigid component it belongs to (63 groups: 50 armour sections such as
`boot_front.L`, `chest`, `helmet_face`, and 13 regions of the undersuit).

- `GROUP_RULES` in `hero/parts.py` maps part names to groups; `BODY_REGIONS` maps the
  undersuit to regions by skin bone.
- `GROUP_CUTS` in `hero/export.py` splits a part that is one piece of geometry but two
  pieces of choreography: the helmet's inner shell is cut so its face section closes
  with the faceplate while the rest clamps on from behind.
- The table (group, tracking bone, pivot, radius) is written to
  `export/aegis-hero.assembly.json` and embedded in the GLB by `finalize-hero.mjs`.
- Timing, start placement and motion of each component are authored in
  `src/player/assemblyManifest.ts`.
- The shoulder missile launchers (`missile_cap`, `missile_pod`, in `hero/armor/back.py`)
  are groups too. The pod is modelled where it stands when deployed; the game keeps it
  sunk behind the shoulder blade and hidden until it is called up
  (`src/combat/Missiles.ts`). The crowd mesh leaves the pods out.

`tools/remotion.py --recut` applies `GROUP_CUTS` and `BODY_REGIONS` to an already baked
mesh with the same code, for trying a new cut without the full bake.

### Changing the design

- Proportions: joint targets at the top of `hero/rig.py`.
- Plate shapes: the outline point lists in `hero/armor/*.py` (metres, x = character's
  left, y = up, z = forward).
- Colours and roughness: `PALETTE` in `hero/blender_io.py`.
- Triangle budget: `EDGE_RULES` / `DEFAULT_EDGE` in `hero/export.py`.
- Thruster mount points: `MOUNTS` in `hero/armor/back.py` and `mounts()` in `hero/parts.py`.

## The pilot

`build_pilot.py` takes `source/pilot-source.glb` (a static mesh), fits the same
skeleton to his joints, solves skin weights in his own modelling pose, then un-poses
the mesh to the rig's T-pose so he plays the same clips as the armour. To swap in a
different character, replace the source file and adjust the joint targets at the top
of that script.

Before binding, `hero/pilot_face.py` gives him a different face on the same mesh.
`repaint` edits the skin texture (clean-shaven, dark-blond hair and brows with
synthesised strands, another eye colour); it picks its regions in head space through
a baked position map, because the scan's face is two overlapping layers with unrelated
UVs. `reshape` then moves the vertices with a list of smooth local warps (`SHAPE`):
jaw, chin, cheekbones, nose, eyes, brow, mouth, ears, haircut. The source file is not
modified; `--source-face` builds him unchanged for comparison. The landmarks at the
top of that module are for this source mesh and need re-measuring for another one.
